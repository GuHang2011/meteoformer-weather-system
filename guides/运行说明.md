# MeteoFormer 区域气象预测系统

**[在线演示](https://guhang2011.github.io/meteoformer-weather-system/)** · **[GitHub 源码与项目展示](https://github.com/GuHang2011/meteoformer-weather-system)**

在线版为合成数据只读快照，支持地图、24 小时时效、单点查询与 PNG / NetCDF 下载；数据导入、训练及新预报生成在本地完整版执行。公开仓库的干净工作副本位于 `publication/meteoformer-weather-system`，前端目录整理为 `frontend`，未包含原学院系统或私有数据。

在现有 Vue 3 / Vite 工程基础上，依据《气象预测系统设计说明书.docx》改造的可运行研究原型。前端继续使用 `frontend`，新增 FastAPI 后端和可实际训练的 Swin + ConvLSTM 小型模型。

当前主入口提供：预报工作台、预报与查询、气象数据、训练记录、阈值告警。学院归档、提交审核、电子盖章、聊天、AI PPT、个人大语言模型配置等旧功能已从入口与构建依赖图移出。旧源代码作为历史参考保留，不启动原 Spring Boot 服务，也不访问原学院数据库。

## 启动

Windows 初次安装（Python 3.12、Node.js 18+）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-model.txt
.\start.ps1
```

之后双击 `start.cmd`，或执行 `./start.ps1`。脚本构建前端，再启动单个 FastAPI 服务，访问 **http://127.0.0.1:8016**。端口被占用时运行 `./start.ps1 -Port 8017`。

普通访客可以浏览与下载预报；管理员可导入数据、训练、生成预报、修改阈值和确认告警。首次启动随机生成管理员密码，位于 `backend/data/initial-admin-password.txt`。也可在启动前设置 `METEO_ADMIN_PASSWORD`，不会创建固定通用密码。

Linux：

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-model.txt
cd frontend
npm ci
npm run build
cd ..
.venv/bin/python -m uvicorn meteo.app:app --app-dir backend --host 127.0.0.1 --port 8016 --workers 1
```

只体验基线预报可安装 `backend/requirements.txt`；模型训练需额外安装 PyTorch。当前实现以 CPU 验证为目标，不声称已验证 GPU 秒级性能。

## 使用流程

1. 登录管理员，进入“气象数据”，导入 NetCDF 或创建 480 小时的合成演示数据。
2. 进入“训练记录”，选数据集，执行至少 3 轮训练。实际经历 1、6、24 小时课程学习阶段，保存日志、权重和测试指标。
3. 进入“预报与查询”，选择数据集与预测方式。持续性基线无需权重；MeteoFormer 可选择相同来源、相同网格的已完成权重，用于新上传的 12 小时起报资料。可选 1–8 个集合成员。
4. 选择气温、降水、风速、湿度或气压，切换 1–24 小时时效。点击网格或输入经纬度查询逐小时预报。
5. 下载真实 PNG 或 NetCDF 文件；到“阈值告警”查看阈值触发记录。

演示数据和由其训练的模型始终标明“合成演示”。它们用于验证流程，不能证明真实气象预报精度。基线保持最新观测值，因此逐小时曲线可能水平，这是基线定义。

## 数据输入

单文件不超过 100 MB。要求一维 `time`、`lat`、`lon` 坐标和下列六个三维变量，时间为连续 UTC 逐小时，输入至少 12 小时。训练建议至少 240 小时，使三个时间分区都可构造 12 小时输入与 24 小时目标。

| 变量 | 含义 | 接受的常用单位 |
| --- | --- | --- |
| t2m | 2 米气温 | °C、K |
| u10 / v10 | 10 米东西 / 南北风分量 | m/s、m s**-1 |
| rh | 相对湿度 | %、fraction |
| precip | 小时降水增量 | mm、m |
| msl | 海平面气压 | hPa、Pa |

支持 `latitude/longitude/valid_time/tp/r/mslp` 别名。每个变量必须具有 `units` 属性；经度必须已转换为 -180–180。ERA5/GFS 累计降水须在导入前按数据产品定义解累计，不能直接把任意累计量当成小时降水。缺少 RH、气压或降水时不会凭空生成这些变量。可用导出的演示 NetCDF 作为结构模板。

导入时重采样到 16、32 或 64 网格；不足 5% 的短时缺失在各时间分区内部插值，边界缺失、连续超过 3 小时的缺失、非有限值和不合理单位会被拒绝。按时间 70%/15%/15% 切分，窗口不跨分区，标准化只拟合训练分区，MOS 只拟合验证分区。

## 后端与存储

`backend/meteo` 包含数据处理、Swin 窗口注意力、ConvLSTM、课程训练、MOS 订正、物理约束、集合扰动、指标、API 和本地索引。气象场保存为 Zarr；SQLite 保存数据集、任务、预报索引、阈值与告警。`backend/data` 是独立气象数据目录，不复用旧系统任何账号或私有文件。

环境变量：`METEO_DATA_DIR` 指定数据根目录，`METEO_ADMIN_PASSWORD` 配置管理员密码，HTTPS 部署设 `METEO_SECURE_COOKIE=1`。只运行一个服务进程；训练与推理互斥，避免原型并发耗尽资源。服务重启会把未完成训练标为中断；运行中的任务不会被伪装为已完成。

完整 HTTP 文档：启动后访问 http://127.0.0.1:8016/docs 。主要接口保留 Word 中的命名：`/api/train/start`、`/api/train/status`、`/api/predict`、`/api/point`、`/api/warning/list`、`/api/forecast/image`。预测接口引用已导入的数据集 ID，取其最新 12 小时作为初值；不接受客户端任意服务器文件路径。所有时间在 API 中为 UTC，页面显示北京时间。

命令行（进入 backend，运行期间不要让另一个进程同时训练或写同一数据目录）：

```powershell
..\.venv\Scripts\python.exe -m meteo.cli demo
..\.venv\Scripts\python.exe -m meteo.cli import example.nc --source ERA5 --hourly-precipitation
..\.venv\Scripts\python.exe -m meteo.cli train DATASET_ID --epochs 3 --samples 16
..\.venv\Scripts\python.exe -m meteo.cli predict DATASET_ID --model-id JOB_ID --members 4
```

## 验证

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest tests -q
cd ../frontend
npm run build
```

浏览器测试位于 `scripts/test-browser.cjs`，使用前端开发依赖 Playwright 与本机 Chromium；首次使用可在前端目录运行 `npx playwright install chromium`。需要先启动端口 8016 的服务。它在本地气象目录创建演示数据与基线预报，验证登录、导出、越界查询恢复、320/390 px 布局和浏览器错误；输出在 `outputs/browser/`。前端静态类型检查运行 `npm run typecheck`。

功能取舍、修正文档中的不合理之处与尚未接入的外部条件，详见 [设计对照与改造记录](设计对照与改造记录.md)。
